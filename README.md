# Генератор черновиков карточек товаров

Локальный прототип принимает JSON с данными прибора, отправляет его в языковую модель через OpenRouter и возвращает черновик карточки.

## Требования

- Node.js.
- API-ключ OpenRouter.

## Установка и запуск

Откройте терминал в папке `descr_ai` и выполните:

```powershell
npm install
```

Создайте в папке `descr_ai` файл `.env` и добавьте в него ключ:

```env
OPENROUTER_API_KEY=ваш_ключ_OpenRouter
```

Запустите сервер:

```powershell
npm start
```

При успешном запуске сервер сообщает, что слушает порт `3000`.

## Как отправить товар через Postman

1. Запустите сервер командой `npm start` и оставьте терминал открытым.
2. В Postman создайте новый HTTP-запрос.
3. Выберите метод `POST` и укажите адрес `http://localhost:3000/product`.
4. Откройте вкладку **Body**, выберите **raw**, затем формат **JSON**.
5. Вставьте JSON товара, например:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления."
}
```

6. Нажмите **Send**. Postman отправит JSON и покажет ответ сервера.

Для обработки обязательны все четыре поля: `name`, `manufacturer`, непустой объект `specs` и непустое текстовое `description`. Если хотя бы одно из них отсутствует или не заполнено, сервер вернёт ошибку и не отправит запрос модели. В `specs` можно указать разные характеристики для разных приборов.

При успешном запросе сервер возвращает JSON с полем `message`, содержащим карточку в Markdown. При ошибке подключения к модели возвращается сообщение об ошибке.

## Что формирует модель

- SEO-заголовок длиной до 70 символов.
- SEO-описание длиной 800–1200 символов.
- Список характеристик из входных данных.
- 3–5 поисковых запросов.
- Коммерческий блок: аудитория и задачи прибора.
- Анализ полноты данных и рекомендации, что уточнить.

Промпт требует писать грамотным русским языком, сохранять технические значения и не придумывать характеристики. Если фактов не хватает, модель должна указать «Данных нет». Требования длины описания не должны выполняться за счёт выдуманных сведений.


## Промпт и принятые решения

Промпт находится в `src/ai.js`. Он задаёт роль технического B2B-копирайтера, формат карточки, ограничения для SEO-полей и правила работы с неполными данными. Технические факты разрешено брать только из переданного JSON; отрасли и задачи нельзя приписывать товару без подтверждения во входных данных.

Сервис принимает один товар на запрос. Проверки обязательных полей выполняются в `src/handler.js`. API-ключ загружается из `OPENROUTER_API_KEY`, а не хранится в исходном коде. Модель и провайдер выбираются в `src/ai.js`.
